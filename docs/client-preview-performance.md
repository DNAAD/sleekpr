# 客户端预览性能与测量

## 调度边界

- 应用拥有一个 `PreviewExecutor`，QtCore 线程池最多运行两个任务，必须在 `QApplication` 清理前收束。
- 每个设计器、设置页或工作台预览队列最多保留一个进行中任务和一个最新待处理任务；只在 GUI 线程发布当前代号的结果。
- 后台只接收冻结的数据与原生计划，执行规划、文本测量和 `QImage` 绘制；`QPixmap`、控件与定位叠加层仍在 GUI 线程。
- 隐藏窗口收到外部通知只记待刷新状态；可见设置页存在草稿时不覆盖表单。显示名称更新不替换工作台数据或非法 JSON。
- 真实打印引擎仍沿用原线程与同步接口，本轮不提供驱动后台提交或打印任务历史。

## 采样方式

`ClientPerformanceMetrics` 仅接收固定阶段和纳秒数，不接收字段内容。每阶段保留最近 512 个样本，记录累计次数及最近样本的 P50/P95；固定容量、互斥保护，长期运行不会无限积累记录。

设置 `SLEEKPR_PERF_TRACE=1` 后，应用退出会输出一次阶段统计。该统计不是用户数据、打印成功证明或物理出纸记录。

可在已配置 Qt 运行时的 PowerShell 中复现固定样例：

```powershell
$env:SLEEKPR_DISPATCH_METRICS = Join-Path $PWD 'build/designer-dispatch-profiled.json'
.\build\sleekpr_label_app_tests.exe designerEditDispatchMetrics -o build/designer-dispatch-profiled.log,txt
if ($LASTEXITCODE -ne 0) { throw '性能样例验证失败' }
Remove-Item Env:SLEEKPR_DISPATCH_METRICS
```

样例使用临时配置、32 个固定文本自动字号元素、20 次参数修改与模拟观察回调，不发送真实打印。测量对象是手动完整属性刷新入口的同步调用时间，不是自然自动应用或拖拽的端到端延迟；等待最终预览在采样区间之外。

## 本机记录

2026-10-20，Debug，保持相同固定输入与操作序列的一次记录：

| 路径 | P50 | P95 |
| --- | ---: | ---: |
| 改造前完整属性刷新调用 | 197.771 ms | 227.450 ms |
| 改造后完整属性刷新调用 | 115.574 ms | 142.481 ms |
| 改造后规划 | 0.214 ms | 0.367 ms |
| 改造后后台栅格化 | 18.455 ms | 21.905 ms |
| 改造后 GUI 发布 | 1.003 ms | 1.182 ms |
| 改造后保存协调 | 43.496 ms | 70.528 ms |
| 改造后完整面板刷新 | 13.400 ms | 15.004 ms |

20 次隐藏设置窗口通知全部延后，未执行外部完整刷新。次数不等于物理磁盘写入次数；保存协调包含锁、读取、合并、备份和提交，规划与栅格化采样也包含最终丢弃的已开始任务。

这些数据受磁盘、字体缓存、构建模式和系统负载影响，不作为硬性耗时断言，也不应推断所有工作负载都获得相同改善。同步保存仍可能造成停顿；后续如后台化保存，需要单独处理冲突反馈、队列合并及退出刷盘，不能只把文件写入随意移到线程。
