# 打印工作台

## 本阶段范围

提供独立的原生桌面标签打印入口：选择模板、填写字段、查看 Qt 原生预览、选择打印机和份数，再提交打印。

不包含批量数据导入、打印历史、自动重试和复杂表格编辑。已有多页模板可以逐页预览，但工作台不修改模板版式。

## 入口和操作

- 启动后显示打印工作台；托盘菜单、托盘单击和设置侧栏均可重新打开。
- 左侧搜索并选择模板，来源包括统一设置中的模板和独立模板库。
- 右侧填写字段或选择字段预设；没有字段定义的旧模板也会从绑定字段、文本占位符、动态二维码和数组数据路径自动生成输入项。
- 自动识别的字段不带入模拟值；尚未填写时阻止打印。确实无需显示的字段可以勾选“留空”，明确传入空文本、空数组或空对象；显式定义为必填的字段仍必须填写。
- 表单与 JSON 模式共用同一份值，额外的数组和占位符字段也会保留。
- 数组使用 JSON 数组输入，行内占位符不会误识别为顶层字段；实际显示的数组项缺少子字段时，会提示对应数组和序号。没有输入项的模板仍可使用高级 JSON 输入。
- 字段默认值与明确选择的预设可以带入；设计器的 sampleData 不会自动成为正式打印值。
- 字段标题显示 `displayName`，悬停可查看原 key；名称优先采用当前模板的显示名称覆盖，其次字段定义，再次内置中文名称，最后回退原 key。JSON、预设和打印取值仍使用 key，不使用显示名称作数据匹配。
- 设计器保存名称、切换模板或返回工作台时自动同步标题；名称刷新不重建输入框，不清除输入值或非法 JSON 草稿，也不会仅因改名额外要求再次确认打印。
- 数据校验通过后，可在字段预设旁保存当前数据为新预设，也可打开预设管理窗口；预设绑定当前模板来源，不会混用同名模板。
- 选择实际可用的打印机和份数后点击打印，份数范围为 1 到 100，单次任务最多 1000 页。
- 同一份多页模板按完整页序复制为一个打印任务；工作台不会静默修改系统默认打印机。

## 输出一致性与状态

工作台与 HTTP 模板打印、预览共享 `TemplatePrintService`，统一处理模板查找、字段合并、模板校验、纸张边距、设备 profile 和 DPI。

预览由 `LabelPreviewImageRenderer` 直接渲染原生绘制计划，正式打印仍交给 `LabelPrintEngine`。预览缩放只改变屏幕分辨率，不改变纸张毫米尺寸。

数据变化后立即废弃旧打印计划，合并等待输入后重新生成预览；错误数据不会复用上一次有效计划继续打印。JSON 格式错误显示行列，缺少必填字段和模板错误会阻止提交。

字段预设只在其目标模板内提供，预设文件损坏会明确阻止打印。保存预设不需要连接打印机，也不会触发打印；无效或不完整的数据不能保存。点击打印时重新读取配置；发现输出已改变时，要求先核对更新后的预览再提交。无效草稿不会在刷新或切换模板时被静默丢弃。

工作台额外启用输入完整性检查；HTTP 调用的既有默认行为保持兼容，不会因旧模板自动发现字段而突然拒绝已有请求。

打印按钮在提交过程中禁用，避免重复点击生成多份任务。“已提交”只表示打印引擎接受了任务，不等于设备已经完成出纸；提交失败不自动重试，需先核对设备是否已经部分出纸。

## 打印前检查与定位

- 中央预览下方提供可折叠的打印前检查列表，错误优先于警告，摘要显示两者数量；没有问题时显示检查通过。
- 校验结果只在检查面板集中展示，底部状态栏不再重复显示就绪、缺失字段、留空或设备不可用；状态栏仅在保存预设、打印提交等操作有结果时出现。
- 字段相关问题使用与表单标题一致的 `displayName`，包括数组及其子字段；未定义名称时按原有名称规则兜底。更新名称同步刷新提示，问题定位、JSON 数据键和 HTTP 错误契约保持不变。
- 列表覆盖当前输入缺失、类型错误、JSON 格式、元素越界、二维码容量、打印机不可用及份数对应的任务页数上限。
- 点击问题或选中后按 Enter，可聚焦字段、JSON 错误行列、打印机或份数；有对应元素时同时高亮原生预览中的区域。明确留空作为警告展示，不强制阻止打印。
- 无有效打印预览时，定位使用当前检查对应的模板快照，只展示纸张和版式外框，并明确标注“版式定位（非打印预览）”。这不是正式打印效果，也不能作为打印计划提交。
- 预览高亮只是界面叠加，不写入模板、PNG 正式预览或打印计划。缩放和设备校准坐标保持一致，首阶段的元素定位回到第一页，不提供复杂表格跨页单元格定位。
- 修改输入后立即清除旧问题和高亮，保留现有 180 ms 合并刷新；份数变化单独合并任务级检查并复用基础打印计划，选择问题不再次生成打印计划。检查阶段不探测设备出纸状态，也不发送测试打印。

## 本地验证

自动化测试使用注入的打印引擎和打印机列表，不发送真实打印任务。覆盖字段往返、错误拦截、当前数据快照、重复点击保护、复制页序、纸张/DPI、模板查找与紧凑窗口布局。

调试版启动命令：`quick-start.cmd -Mode Debug`。默认 Release 包需单独重新打包，Debug 构建不会更新正式包。

### Windows 增量构建检查

MSVC 的依赖输出按本机语言包自动探测，并使用 UTF-8 解码，不能直接假定系统安装了英文编译器语言包。Ninja 必须记录头文件依赖，否则控件布局更新后可能混入旧对象文件，出现堆越界和打开设计器崩溃。

CTest 额外检查实际客户端对象的关键头文件依赖，并运行 `sleekpr --smoke-test-designer`：从工作台、设置页打开设计器以及重复打开。该隔离模式仅使用临时配置，不监听 HTTP、不显示托盘或窗口、不调用打印引擎，不读写操作员的模板配置。
