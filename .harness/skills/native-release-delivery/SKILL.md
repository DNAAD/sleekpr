# 原生 Release 安全交付

## 入口与权限

先读 [Windows 构建知识](../../wiki/windows-build.md)，具体命令统一使用 [验证技能](../verification/SKILL.md)。复用现有打包脚本和模块，不另写一套复制、删除或版本命名逻辑；不扩展到安装器、签名或在线发布。

本技能不授予提交、推送、真实打印或关闭客户端的权限。遇到占用时请操作员保存并从托盘退出，不默认传 `-StopRunning`。源码 dirty 可以如实交付，不为“变干净”擅自提交。

## 交付检查点

1. 核对实际仓库、构建缓存、Qt 根目录与目标模式。普通 Debug 构建不会更新 `dist/sleekpr-release`，已有 EXE 的启动器也不会自动重建。
2. 运行默认 `package-portable.ps1`，保留独立 `build-release`。正式门禁必须是测试实际总数大于零、失败为零、跳过为零；不固定历史测试数量。有任意失败或跳过立即停止，不能改成 `-NoTests` 后继续报告正式通过。
3. 由脚本在仓库 `dist` 下的独立暂存目录部署，拒绝越界、危险尾随路径及重解析点，移除调试/测试产物，核对部署 EXE 与构建产物摘要。清理或移动前核对解析后的绝对路径和目录树，不能先清空正式目录或整个构建缓存。
4. 通过 PE 能力标记后读取 Release 身份，再从暂存目录隔离运行版本诊断和设计器冒烟。隔离须清除开发 Qt 插件/QML 路径和 PATH 注入，使用包内 `qt.conf` 与本地运行库；不能直接用未知旧 EXE 试参数。
5. 核对 `manifest.json`、ZIP 及 `.zip.verification.json` 的构建身份和摘要。清单不记录自身摘要，ZIP 整体摘要在包外；`sourceDigest` 不是二进制摘要，未知 Git 状态不记 clean。
6. 候选目录与 ZIP 都通过后才发布正式输出，保留旧三件套到候选验收结束；发布前再次检查客户端占用。`-NoTests` 只能得到带 `unverified` 标记的候选目录和归档，不得改名或复制成正式包。

## 失败与回滚

- 测试、部署或冒烟失败：保留旧正式目录，不跳过失败继续发布。先保留退出码与逐用例日志，定位真实断言；重复运行通过不是首次失败根因已证明，也不能降低门禁。
- 发布移动失败：[PortablePackage](../../../packaging/PortablePackage.psm1) 按记录逆向移动；核对旧目录、ZIP、验证记录是否一致。失败暂存目录可能保留，逆向操作失败会告警，不能无条件宣称“已完全回滚”。
- 清理前校验绝对路径及重解析点，不能用跨 shell 拼接的递归删除或未经校验的计算路径清理现场。
- 用户要求回退已发布旧版本时，先明确目标与替换范围，找到可信且已验收的旧 ZIP、配套验证记录和包内清单，确认客户端已退出。成功发布不保证保留历史解包目录；需要重建旧候选时先校验归档条目和路径，再解压到独立暂存目录，不向正式目录直接解压覆盖。
- 旧候选重新核对摘要、隔离身份及冒烟后，保留当前目录、ZIP 和验证记录，再按记录执行可逆替换；缺少可信旧产物或替换授权时停在诊断/方案阶段。
- 当前公开脚本只有发布失败时的自动回滚，没有历史包一键回退参数。不要伪造 `-Rollback`，不要用 Git 重置或恢复操作员 `settings.json` 代替二进制回退；回退配置属于不同任务。

## 结果记录

交付说明给出：正式或候选状态、目录/ZIP/清单/验证记录路径、实际 BuildInfo、测试总数/失败/跳过、隔离诊断和冒烟结果、摘要核对结果。失败时记录停止阶段、旧产物与恢复状态，不报告正式包完成。

说明仍未执行的真实出纸、无 Qt 新机器验证、签名或安装器验收；本机隔离通过不等于这些项目已完成。仅 Harness/文档修改做文档验证，不为满足本技能而无条件重打包。
